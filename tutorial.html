How to generate the GitHub token

Step-by-step guide to creating a token that lets the roadmap save directly to the repository.

🔗 Open the token creation page on GitHub

This link already opens straight into the token creation screen — Steps 1 and 2 below (getting there via the menu) are already taken care of. After clicking, skip straight to Step 3.

⚠️ Token expiration: set the Expiration field to the end of December (e.g., 12/31/2026). When the token expires, the "Save to GitHub" button will stop working until someone generates a new one and reconnects — set a reminder to renew it before it expires.
1

Go to Developer settings skip if you used the link above

In the top-right corner of any GitHub page, click your profile picture → Settings. In the left-hand menu, scroll to the bottom and click Developer settings.

Simplified illustration of GitHub's profile menu — the real layout may vary slightly.
2

Open "Personal access tokens → Fine-grained tokens" skip if you used the link above

Inside Developer settings, in the side menu, click Personal access tokens and then Fine-grained tokens. Click the green Generate new token button.

"Fine-grained tokens" (highlighted in blue) is the recommended option — safer than classic tokens.
3

Give it a name and set the expiration to December

In Token name, enter something like QA Roadmap. In Expiration, choose a custom date and pick Dec 31 of this year. This avoids an "eternal" token floating around, but it does require renewal — add it to the team's calendar.

4

Limit access to this repository

Under Repository access, select Only select repositories and choose the roadmap's repository. This way the token can't see any other repository of yours.

5

Turn on the "Contents: Read and write" permission

Scroll down to Permissions → Repository permissions. Find the Contents row and change the dropdown from "No access" to Read and write. This is the only permission required — everything else can stay as-is.

6

Generate and copy the token

Scroll to the bottom and click Generate token. The token appears only once on the next screen, something like github_pat_11AB.... Copy it right away — if you leave the page without copying it, you'll need to generate another one.

7

Paste the token into the roadmap page

Go back to the roadmap → ✏️ Edit roadmap → Sync tab → click Save to GitHub (or Connect) and paste the copied token. It's saved only in that browser — it's never sent to the repository or shared with anyone else.

🔁 When the token expires (end of December, if you followed step 3), the "Save to GitHub" button will show an invalid-token error. Just repeat these steps to generate a new token and click 🔑 Switch / disconnect token in the Sync tab to reconnect.

❓ "My repository doesn't show up under Resource owner"

This is a known GitHub limitation, not something you did wrong. The Resource owner field, on the fine-grained token creation screen, only lists your own personal account and organizations you belong to. If the repository lives under someone else's personal account (not an organization) and you're just a collaborator — not the owner — GitHub won't offer that account as an option. Fine-grained tokens simply don't support this scenario yet.

The fix is to use a classic token instead of a fine-grained one. It works exactly the same way inside the roadmap — the page needs no changes at all.

A

Generate a classic token

GitHub → profile picture → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → Generate new token (classic).

🔗 Open classic token creation
B

Name, expiration, and scope

Give it a name (e.g., QA Roadmap) and set the expiration to end of December, same as the fine-grained token. Under Select scopes, check the repo box (Full control of private repositories) — classic tokens don't have a "this repository only" scope, so repo is the most restrictive option available that will still let you save.

C

Generate, copy, and paste into the roadmap

Click Generate token, copy the value (it only appears once), and paste it into the roadmap the same way: ✏️ Edit roadmap → Sync tab → Save to GitHub.

⚠️ A classic token with the repo scope grants access to every private repository that person has access to, not just this one. It's currently the only way around GitHub's limitation for outside collaborators — if that's a concern, consider moving the repository into a GitHub Organization and adding the QAs as members: fine-grained tokens then work normally again, because the organization shows up under Resource owner.

❓ Error "Could not save to GitHub: Not Found"

This error (404) shows up when the token itself is valid, but the GitHub API can't find the repository for that specific token. The most common causes, in order of likelihood:

1

Add the person as a collaborator (and have them accept the invite)

Whoever owns the repository should go to Settings → Collaborators and teams → Add people, type the teammate's GitHub username or email, and confirm.

The teammate gets an invite by email (or sees it at github.com/notifications) and needs to click Accept invitation. Only after that does their token — classic or fine-grained — see the repository. Sending the invite without it being accepted is not enough.

2

Wrong scope on a classic token (private repository)

If the repository is private, the token needs the repo scope (Full control of private repositories) — public_repo is not enough and results in this same error. Generate a new token making sure that box is checked.

3

Token pasted with a stray space or line break

When copying from the GitHub screen, check that no space snuck in before/after it. Paste it again directly from the "Copy" button on the token generation screen.
