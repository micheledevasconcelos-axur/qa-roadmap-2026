Como gerar o token do GitHub

Passo a passo para criar um token que permite ao roadmap salvar diretamente no repositório.

🔗 Abrir a página de criação do token no GitHub

Esse link já abre direto na tela de criação do token — as Etapas 1 e 2 abaixo (chegar até essa tela pelo menu) já ficam resolvidas automaticamente. Depois de clicar, pule direto para a Etapa 3.

⚠️ Validade do token: defina o campo Expiration até o final de dezembro (ex: 31/12/2026). Quando o token vencer, o botão "Salvar no GitHub" vai parar de funcionar até alguém gerar um novo e reconectar — marque um lembrete para renovar antes do vencimento.
1

Acesse as configurações de desenvolvedor pode pular se usou o link acima

No canto superior direito de qualquer página do GitHub, clique na sua foto de perfil → Settings. No menu à esquerda, role até o final e clique em Developer settings.

Ilustração simplificada do menu de perfil do GitHub — o layout real pode variar levemente.
2

Abra "Personal access tokens → Fine-grained tokens" pode pular se usou o link acima

Dentro de Developer settings, no menu lateral, clique em Personal access tokens e depois em Fine-grained tokens. Clique no botão verde Generate new token.

"Fine-grained tokens" (destacado em azul) é a opção recomendada — mais segura que os tokens clássicos.
3

Dê um nome e defina a validade até dezembro

Em Token name, coloque algo como QA Roadmap. Em Expiration, escolha uma data personalizada e selecione 31/12 deste ano. Isso evita um token "eterno" circulando, mas exige renovação — anote no calendário do time.

4

Limite o acesso a este repositório

Em Repository access, marque Only select repositories e escolha o repositório do roadmap. Assim o token não enxerga nenhum outro repositório seu.

5

Ative a permissão "Contents: Read and write"

Role até Permissions → Repository permissions. Procure a linha Contents e mude o menu de "No access" para Read and write. Essa é a única permissão obrigatória — as demais podem ficar como estão.

6

Gere e copie o token

Role até o final e clique em Generate token. O token aparece uma única vez na tela seguinte, algo como github_pat_11AB.... Copie imediatamente — se sair da página sem copiar, é preciso gerar outro.

7

Cole o token na página do roadmap

Volte para o roadmap → ✏️ Editar roadmap → aba Sincronização → clique em Salvar no GitHub (ou Conectar) e cole o token copiado. Ele fica salvo só nesse navegador — nunca é enviado para o repositório nem compartilhado com mais ninguém.

🔁 Quando o token vencer (fim de dezembro, se você seguiu o passo 3), o botão "Salvar no GitHub" vai mostrar um erro de token inválido. Basta repetir estes passos para gerar um novo token e clicar em 🔑 Trocar / desconectar token na aba Sincronização para reconectar.

❓ "Meu repositório não aparece em Resource owner"

Isso é uma limitação conhecida do GitHub, não um erro seu. O campo Resource owner, na tela de criação do token fine-grained, só lista a sua própria conta pessoal e organizações às quais você pertence. Se o repositório está na conta pessoal de outra pessoa (não numa organização) e você é apenas colaborador(a) — não dono(a) — o GitHub não oferece essa conta como opção. Tokens fine-grained simplesmente não suportam esse cenário ainda.

A solução é usar um token clássico (classic) em vez de fine-grained. Funciona exatamente igual dentro do roadmap — a página não precisa de nenhum ajuste.

A

Gere um token clássico

GitHub → foto de perfil → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → Generate new token (classic).

🔗 Abrir criação de token clássico
B

Nome, validade e escopo

Dê um nome (ex: QA Roadmap) e defina a validade até o fim de dezembro, igual ao token fine-grained. Em Select scopes, marque a caixa repo (Full control of private repositories) — tokens clássicos não têm um escopo "só este repositório", então repo é o mais restrito disponível para conseguir salvar.

C

Gere, copie e cole no roadmap

Clique Generate token, copie o valor (aparece só uma vez) e cole no roadmap do mesmo jeito: ✏️ Editar roadmap → aba Sincronização → Salvar no GitHub.

⚠️ Um token clássico com escopo repo dá acesso a todos os repositórios privados que essa pessoa tem acesso, não só a este. É a única forma de contornar a limitação atual do GitHub para colaboradores externos — se isso for uma preocupação, considere mover o repositório para uma Organização do GitHub e adicionar as QAs como membros: nesse caso, o token fine-grained volta a funcionar normalmente, porque a organização passa a aparecer em Resource owner.
